## After installing

- Change the skill chain wherever the project's `CLAUDE.md` states it: a "Skills" section in the template's layout, or a sentence elsewhere. This version changes two things in it: `code-review` moves after `commit` and runs once per unit of work, and `ship` runs once per task, at the end. In `ae-kit-templates/CLAUDE.md.template` the chain reads `scope → design → adversarial → build → verify → commit → code-review` **once per unit of work**, then `ship` once, followed by a paragraph that explains it. Make those two changes and add that paragraph next to the chain, keeping any skill or order of the project's own that the template does not have. Show the owner the current wording and the new one, and edit only with their permission: the installer never touches `CLAUDE.md`.
- Change the trigger of rules R3 and R5 in the rules table of `CLAUDE.md` from `skill:commit` to `skill:ship`, as the template has them: in this version `commit` never pushes, and `ship` is the skill that closes the task and verifies the push. If the project numbers those rules differently, change the rows whose verification is the task's `status:` and the line in `logs/deploy-checks.md`. Ask the owner before editing `CLAUDE.md`.
- Add to "Git conventions" in `CLAUDE.md` the template's bullet that starts with "Whether a pull request verifies without publishing", and answer it there for this project, reading its CI and deploy workflows once: `ship` asks for that answer instead of re-deriving it per task. Ask the owner before editing `CLAUDE.md`.
- Include the `.gitattributes` the installer wrote (`logs/tasks/*.md merge=union`) in the commit of what the install wrote, so two branches that append to the same task log merge without a conflict. If the project already declares another merge rule for those paths, the installer wrote nothing and printed the exact line to paste: show it to the owner and paste it only with their permission. Ask the owner before committing.
- **Only a project whose `.ae-kit-customized` lists `.claude/skills/scope/SKILL.md`:** keep the kit's `scope` skill, not the project's earlier customization of it: what it customized, splitting a task into units, is what this version ships. The owner already decided this.
