# Kit 0.40.1

## Before installing

- Tell the owner where the kit comes from now. From this version it is published in `agantoniolar-lgtm/angee-public` and installed from there: `gh api repos/agantoniolar-lgtm/angee-public/contents/install.sh -H "Accept: application/vnd.github.raw" | bash -s -- <path>`. The repo that used to be `agantoniolar-lgtm/angee` was renamed `agantoniolar-lgtm/angee-private`. It stays private and keeps every earlier version as a commit titled `kit <version>`. `angee-public` holds no version before 0.40.1. GitHub sends the old name `agantoniolar-lgtm/angee` to `angee-private`, so an install command or a check written with the old name still works, but only while no repo named `angee` exists again. Never create one: a project still on an earlier version would stop finding the kit. Nothing in the project needs editing for this.
- A project with a committed, well-formed `.ae-kit-manifest` installs as usual from `angee-public`, with no variable, and adds `--notes-done 0.40.1` once the steps here and those of any earlier version printed above are done.
- **Only a project with no committed, well-formed `.ae-kit-manifest` whose `.ae-kit-version` names a version older than 0.40.1:** the installer compares the project against the version it has installed, as published, to tell the project's own edits from an older kit and to know which files the kit stopped shipping. It reads that version from the history of the repo it installs from, and `angee-public` has none. So this install takes its kit from `angee-private`, with the variable on the installer itself, to the right of the `|`: `gh api repos/agantoniolar-lgtm/angee-public/contents/install.sh -H "Accept: application/vnd.github.raw" | AE_KIT_REPO=agantoniolar-lgtm/angee-private bash -s -- <path> --notes-done 0.40.1`. Written before `gh`, the variable reaches `gh` and not the installer, and the install goes ahead with no base. A manifest that is missing, that git does not track, or that has a line out of shape counts as none: the installer does not trust it either.
- **Only a project with no committed, well-formed `.ae-kit-manifest` whose `.ae-kit-version` names a version older than 0.40.1:** before that install, do the "Before installing" steps of every earlier version printed above, in order. Among them, the guide `ae-kit-templates/local-adjustments.md`, steps 1 to 6, turns each kit file the project edited into a local adjustment. Read the guide as the notes of 0.38.0 say, from `angee-private`, which by then holds this version of it. Its step 1 block picks `angee-private` by itself for a version older than 0.40.1: nothing has to be set for it.
- **Only a project with no committed, well-formed `.ae-kit-manifest` whose `.ae-kit-version` names a version older than 0.40.1:** then run that same install command once with `--dry-run` added, and read its report before the real one. With the variable in place it says "What the project changed, and what the kit dropped, were judged against the published v<installed version>". If it says instead "The files the kit stopped shipping could NOT be identified", the variable did not reach the installer: fix the command and run the dry run again. Do not install without that line. The files the dry run lists under "EDITED IN THE PROJECT" still hold an edit that steps 1 to 6 did not convert, and the install would overwrite it: convert them first.
- The installer can only remove a file the kit stopped shipping when the version it compares against still had it. Files the kit dropped before that version, left on disk by an install that had no manifest, it does not see. After the install, check whether any of these is still there: `.claude/skills/commit/scripts/check-deploy-status.sh` (dropped in 0.37.0; the kit's copy lives in `ship`), `ae-kit-templates/COWORK_PROJECT_INSTRUCTIONS.md.template` (dropped in 0.31.1), `ae-kit-templates/kit-reconciliation.md` (dropped in 0.38.0) and `scripts/control-center-seed.mjs` (dropped in 0.40.0). Nothing in the kit reads them. List the ones present to the owner and delete them only with their permission, in the install commit. If `.ae-kit-excluded`, `.ae-kit-local` or a row of "Local kit adjustments" names one, tell the owner, and remove that line or row with their permission too.
- **Only a project whose `.claude/skills/code-review/SKILL.md` carries a local edit that caps the review rounds per unit at three:** if this same install printed the notes of 0.38.0, two of its lines no longer hold. They say the kit ships that cap as its default and tell you to discard the edit as matching, or to delete a "Local kit adjustments" row for it. From this version the kit's cap is two. Do not discard the edit as matching and do not delete such a row: ask the owner whether to keep the kit's two (put the file back to the version the project installed, as step 6 of the guide `ae-kit-templates/local-adjustments.md` does, so the install replaces it without listing it as edited) or to keep three (turn the edit into a row of "Local kit adjustments", as the guide `ae-kit-templates/local-adjustments.md` says, and record the owner's `decision` on each unit that reaches two rounds, since the appender refuses a third without it). Edit nothing until they answer.

## After installing

- Commit what the install wrote, `.ae-kit-manifest` included, once (also when an earlier version's notes in this same install ask for it), after showing the owner the report and with their permission. End its message with `Task: none`. From that commit on, the project installs from `angee-public` with no variable.
- Tell the owner about `install.sh --ref <tag>`. `angee-public` has no tags, so `--ref v0.31.0` and the like work only against `angee-private`: `… | AE_KIT_REPO=agantoniolar-lgtm/angee-private bash -s -- <path> --ref <tag>`. A plain install takes `main` and needs no tag.
- Tell the owner the review rounds per unit drop from three to two. Nothing needs editing. When a unit's second review round still leaves a blocking finding, `scripts/task-log-append.mjs` refuses a third round, and the session takes the unit to the owner as a class A decision: accept the risk in writing, re-scope the unit, or open one more round with a `decision` that names the unit. A unit already at two or more rounds whose last one left a blocking finding needs that decision before its next round.
- **Only a project whose "Local kit adjustments" in `CLAUDE.md` has a row that sets the review rounds of `code-review` at three:** the kit's rule is now two, and the row no longer matches what the appender enforces, since the script refuses the third round without the owner's decision. Show the owner the row and ask whether to keep the kit's two, deleting the row and its local files, or to keep three by recording the owner's decision on each unit that reaches two. Edit `CLAUDE.md` only with their permission.
- Tell the owner what changes in how a finding is recorded. Nothing needs editing. `scripts/task-log-append.mjs` now writes a finding only with `--severity blocking` or `--severity flag`. Findings already written with other words (`minor`, `nit`, `non-blocking`…) stay valid and still read as not blocking. A finding may also carry the fields of the new `ae-kit-templates/severity-rubric.md` (level, evidence, defect type, destination, and for a deferred one `reopens-if` and `due`). The rubric says which values go together, and the appender and `check-task-log.mjs` refuse a pair that cannot happen.
- Tell the owner that a flag is now fixed in a new unit, not inside the unit whose round raised it. The `fix` of such a flag carries `--commit <sha>`, and the appender refuses it unless a round of another unit reviewed that commit after the flag. The one exception is a flag raised by a round that also left blocking findings: that unit is amended anyway, and the flag may be fixed in the same amendment.
- Tell the owner the kit now carries an MIT license, in `LICENSE` at the root of `angee-public`. The installer does not copy it into the project. A project that redistributes the kit's files, inside its own repo or otherwise, keeps a copy of that `LICENSE` with them: MIT requires its notice in every copy. A project that is not redistributed has nothing to do.
