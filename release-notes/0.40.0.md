# Kit 0.40.0

## Before installing

## After installing

- Add the line `/roadmap.html*` to the project's `.gitignore` if it is not there, before any commit this install asks for (including one in the notes of an earlier version printed above), so it travels in the install commit. It changes a file of the project, so say so to the owner when showing the report. From this version every close writes `roadmap.html` at the project root, and the pattern also covers the `roadmap.html.tmp-<pid>` file an interrupted run leaves.
- Commit what the install wrote, `.ae-kit-manifest` and the `.gitignore` line above included, once (also when an earlier version's notes in this same install ask for it), after showing the owner the report and with their permission. End its message with `Task: none`.
- Tell the owner what changes in the control center. Nothing needs editing. The page now shows only the class A decisions: open cards, "Upcoming" (taken from the `upcoming` cards alone) and what was decided. The tasks view, the agent reports and their read marks are gone. Agent reports stay in `logs/subagents/`.
- Tell the owner how opening and closing change. Nothing needs editing. `open-session` no longer reloads the page: it makes three calls (load the tools, watch, query the decided cards) and reads `ae-kit-templates/control-center.md` only when a decision waits to be recorded. `session-log` now records the decisions still pending before it writes the session log, and writes a line starting with `control center:` that says what it did. The next opening repeats that line when it says `not done`.
- If this same install printed the notes of 0.39.0, two of its lines no longer hold. Opening does not reload the page, and the script that line names, `scripts/control-center-seed.mjs`, is retired in this version (see below). Adopting a page no longer regenerates its tasks and upcoming items, and deletes nothing: it writes the project's name, language and the page's marker into `meta/project`, and leaves the rest of the database where it is.
- A page that already exists needs one republish and one migration, in this order. Do them only for a project whose `.ae-control-center` has a `url`. A project with no page, or with `declined`, skips the steps below about the page's republish, migration, tabs and old documents.
- Ask the owner before republishing: it replaces the page that the owner sees. With their permission, follow "Republishing a page that already exists" in `ae-kit-templates/control-center.md`. Read the page, then publish `ae-kit-templates/control-center.html` over its same `url`, without `capabilities` and without `icon`. Leaving both out keeps the page's database, its decisions and its notices. Then write the marker into `meta/project` and run "The one-time migration to `recorded`" of the same guide.
- The migration moves each decided card that already has a `logEntry` to `status: recorded`. It writes nothing into any task log. A decided card with no `logEntry` is left for the guide's section 2 to record. Until the page carries the marker, the session writes only `logEntry`, as before, so installing first and republishing later loses nothing.
- If the republish, the marker or the migration fails, tell the owner what was not done and why. Then say it in this session's `control center:` line of the session log, with the words `not done`. Do not publish a second page. A migration that stopped part way is continued by the next close.
- Ask the owner to reload any tab of the page that was open during the republish. That tab still runs the old page, which does not know `recorded` and draws the moved cards wrong until it is reloaded.
- The page's old documents stay in its database, unread and undeleted: the collections `tasks`, `upcoming`, `reports` and `reportsRead`, and the doc `meta/sync`. Do not delete them.
- **Only a project whose control center page was published from the 0.39.0 template and has no marker in `meta/project`:** republish and migrate it as above, with the owner's permission. Until then, its decisions are recorded with `logEntry` alone, and the opening's query also returns the cards already recorded.
- **Only ae-setup:** its page was already republished with the marker and migrated. Run the migration's check query once, which only reads, and republish nothing unless the marker in `meta/project` differs from the template's.
- Tell the owner that `check-task-log.mjs` and `check-log-layout.mjs` now print one line when everything passes, and the detail only when something fails. Nothing needs editing.
- Tell the owner about the roadmap. Nothing needs editing. At every close, `session-log` step 5a runs `node scripts/roadmap.mjs` and writes `roadmap.html`, a page that only reads the repo and needs no network. It shows the tasks authorized to start without asking in a block of their own, then the queue of `## Next session` from `STATUS.md` in its order, one lane per epic of `PRODUCT.md` with its active tasks, and one line with the epics that only have backlog. `node scripts/roadmap.mjs --open` opens it. It is separate from the control center and changes nothing on that page. If the script fails, the close goes on and the session log says so.
- `scripts/control-center-seed.mjs` is retired: no skill runs it and the page does not read what it writes. When the project has a base (a `.ae-kit-manifest`, or the published version its `.ae-kit-version` names), the installer removes the installed copy if it is unchanged and lists it under "RETIRED". With no base, the installer removes nothing. When `.ae-kit-version` names an earlier version, the report says the files the kit stopped shipping could not be identified. If `scripts/control-center-seed.mjs` is still on disk after the install, tell the owner: it can be deleted with their permission. Its suite was never installed in a project.
- A project with a base that changed `scripts/control-center-seed.mjs` keeps it: the report lists it as changed and left in place. Nothing runs it any more. Delete it only with the owner's permission.
- If `.ae-kit-excluded` declares `scripts/control-center-seed.mjs`, that line is no longer needed: propose to the owner removing it, and remove it with their permission. The installer does not fail on the line and does not report it. It also never removes a declared path, so a copy of the seed that is still on disk stays, and can be deleted with the owner's permission.
- **Only a project with its own `ROADMAP.md` at the root:** `roadmap.html` is a different file and never overwrites it, but both now show the order of work. Tell the owner about the overlap. Then propose how to adapt `ROADMAP.md` to the new roadmap, and edit it only with the owner's permission. Until its `STATUS.md` has a `## Next session` section and it has a `PRODUCT.md`, its `roadmap.html` shows no queue and lanes by status, not by epic: say so, so the owner decides what `ROADMAP.md` keeps.
