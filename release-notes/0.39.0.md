## After installing

- Commit what the install wrote, `.ae-kit-manifest` included, once (also when an earlier version's notes in this same install ask for it), after showing the owner the report and with their permission. End its message with `Task: none`: `ship` now runs `scripts/check-push-tasks.mjs` before every push, session close included, and that check holds any commit in the push that has no `Task:` line.
- Run `node scripts/check-push-tasks.mjs --session-close --no-fetch` and read its exit code from the command itself, never through a pipe. It only reads. Exit 2 that names no commit-msg hook means `ship` can no longer push at all, because exit 2 is never a pass: add the hook as `ae-kit-templates/SETUP_CHECKLIST.md.template` gives it for `scripts/check-commit-task.mjs` (the hook git runs must be executable). Adding a hook needs the owner's permission. Exit 1 names unpushed commits with no `Task:` line, or with code of a task that is not `done` or `dropped`. Show that list to the owner: those commits hold the next push until their task ships.
- Add the "Suite command" line to the Stack section of `CLAUDE.md`, copied from `ae-kit-templates/CLAUDE.md.template`, with the project's own command: the one command that runs every suite, from a clean install and build when the project has dependencies or a build step. Read it from what CI or R4 already runs, and confirm it with the owner. With no tests yet, write `TBD — deferred`. `build` passes this command, and no other, to `integrate-unit.mjs integrate --verify`. Without it, a delegated unit is not integrated, and units are built by a single writer in the main checkout. Editing `CLAUDE.md` needs the owner's permission.
- **Only a project whose `CLAUDE.md` carries the delegation bullet and whose Stack has no "Suite command" line:** none of its delegated units integrates until the line exists. Read what its CI and its test scripts run (for example `npm ci`, `npm run lint` and `npm test`). Propose a command built from those to the owner, adding the build (for example `npm run build`) if the owner wants it checked too, and add the line once approved.
- Tell the owner what the next `open-session` does, since the project has no `.ae-control-center`: its last line offers the control center, a private claude.ai page where the owner takes class A decisions. The choices are (a) create a new page, (b) adopt a page the owner already has, by its link, or (c) not now, and it also asks the page's language, `en` or `es`. Nothing needs editing now. That session needs the Artifact tool, `ArtifactData` and `ArtifactComments`. A subagent or a print session has none of them, and then the offer is skipped with one line saying why. Creating, adopting and the language are the owner's call. The answer is saved in `.ae-control-center`, a file at the repo root that is committed, not ignored. `open-session` writes it and never commits it, so the session's next commit carries it, ending with `Task: none` unless it belongs to a task. From then on every opening watches the page, records what the owner decided there into task logs, and reloads it with `node scripts/control-center-seed.mjs`, which only reads the repo and writes its output to a scratch file.
- **Only a project that already has a control center page built by hand, outside the kit (for example from a `docs/control-center/` folder):** at the offer, the owner may answer (b) with its link. Before adopting, read the page's card ids with `ArtifactData` `query` on `decisions`, which only reads. Adoption passes each id through a quoted heredoc inside `$( )`, and in bash 3.2 or `sh` that does not protect an id holding `)`. If any id holds anything other than letters, digits, `-` and `_`, show it to the owner before adopting. Adopting republishes the kit's page over the old one. Its decisions, reports and read marks stay. Its tasks and upcoming items are regenerated from the repo, and the old ones deleted. Decided cards that no task log cites in the `card <id>` form are listed to the owner before being marked as old. Once adopted, the files the project used to build and load its page no longer feed it (for example `docs/control-center/control-center.html` and a seed script next to it). Propose retiring them, together with the `STATUS.md` line saying the page is watched at open, which `open-session` now does itself. Deleting files and editing `STATUS.md` need the owner's permission.
- Read each row of "Local kit adjustments" that modifies `scope`, `open-session`, `build`, `commit` or `ship` against the new skill. `scope` gained a step 7 (the plan review), so its old steps 7 and 8 are now 8 and 9. `open-session` gained a step 5b (the control center) and reports `integrate-unit.mjs status` for every task in progress. `ship` gained steps 1b and 2b. If a row cites a step by number, or now contradicts the skill, show it to the owner. Editing `CLAUDE.md` needs their permission. **Only a project with a row that modifies `scope` and `open-session`:** that row is one of these.
- If `CLAUDE.md` or a row of "Local kit adjustments" says the owner approves how a task splits into units, or that a class A question goes on a control-center card, `ae-kit-templates/decision-classes.md` now settles both. A split is class B once `scope-reviewer` has run, and a split that changes what gets built stays class A. A class A question goes on a card when the project has a control center. Propose to the owner removing the duplicate or settling the contradiction. Editing `CLAUDE.md` needs their permission.
- Tell the owner how pushes change. Nothing needs editing. Before closing a task, `ship` runs `integrate-unit.mjs status` on it and discards only the leftover worktrees and branches of units already integrated. Files git ignores in such a worktree, like a `.env` copied by hand, go with it, and `ship` lists them in the task log. `ship` holds a push that would carry code of another task that is not `done` or `dropped`. The task that ships stays `done`, and the hold is written in `STATUS.md` under "Next session". A session close holds that code too, so it stays local until its own task ships. Where the tracked branch is production, this is what keeps half a feature away from users.
- Tell the owner two more changes. Nothing needs editing. `scope` now has its plan reviewed by `scope-reviewer` (`.claude/agents/scope-reviewer.md`, installed with this version) before the owner sees it. The owner gets the class A questions and the unit count, not the split itself, unless that review could not run. And `integrate-unit.mjs integrate` now lets through a unit whose last review round left blocking findings, once each of them is closed by a `decision`, the owner accepting its risk in writing. It prints which decisions it relied on.
